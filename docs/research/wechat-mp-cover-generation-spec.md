# 微信公众号文字封面生成规范 v1：头条一行，次条两行

适用于多图文消息里的**短标题文字封面**，目标是复现生财有术样本的阅读效果，而不是复制其品牌。建议固定两套版式、共用一套字体和配色：**头条把一个关键词横向展开，次条把两个意群叠在方形中心；两者只强调第一行。** 同一篇文章若要兼顾两种展示位，分别排版，不从头条硬裁方图。

下图是按本文规则生成的**自定义示例**，不是生财原图。左为头条，中为次条放大图，右为同一次条缩到 56 × 56 px 的效果。换成黑体和蓝灰底后，仍可凭行数、留白和色条认出是同一套封面。

**样本量感。** 用 RGB 三通道均大于 218 的像素取白字外接框（不把橙条算作字高）；色条以 `R>155, G<135, B<85, R−G>65` 取框。对两张头条 CDN 图，字宽占画宽 **49%–52%**，字高约占画高 **28%**；色条宽约 **49%**、厚约画高 **11%**，上部藏在白字后。`三天 / 体验营` 方图的两行总墨迹宽 **89%**、高 **64%**，色条宽 **67%**、厚 **8%**。截图的两枚 56 px 次条中，白字最宽处分别约 **47 px、30 px**：短词不必强行撑成一样宽。字形有宋体式粗细对比，但不能据此识别具体字体文件。

**背景是单色系，不是平涂。** 以 `FDE交付` 素材为例：顶边中心附近 `(50%,2%)` 为 `#02A998`，左上 `(2%,2%)` 为 `#01443B`，左下 `(2%,98%)` 为 `#002722`；橙条的高频实色为 `#E03A00`。聚光来自**上方中央亮、两侧和底部暗**，不是文字发光。截图有缩放和界面遮罩，故用素材量色，用截图判断阅读尺寸；这些是样本值，不是品牌标准色。

## 2. 生成规范：先定文案，再按展示位排字

**输入分三项：** `articleTitle` 留给微信卡片；`lines` 是真正入图的有序短词数组；`theme` 是同一账号固定使用的主题。不要把文章标题自动截前 N 字：先找“对象 + 动作/结果”，删除铺垫、期数和已由卡片说明的信息。例如“听完 FDE 大会，我做了个 AI 工作台给老板试用，首单就收了 6000”取的是 **FDE交付**，不是“听完FDE”。次条按语义断行，保留 `FDE`、`AI` 等完整词。建议头条 3–6 个汉字量级、次条每行 2–3 个；**实际限制用字形测量，不按字符数折算英文宽度**。

### 版式与坐标

`W,H` 为当前画布宽高，原点在左上。下表使用相同的 400 px 画高便于换算；可等比放大，不横向拉伸字体。所有尺寸按可见字形（墨迹），不是文本框、字号或行盒计量。

| 项目 | 头条 `lead` | 次条 `secondary` |
| --- | --- | --- |
| 独立画布 / 文字 | **940 × 400**（精确 2.35:1），一行 | **400 × 400**（1:1），两行，各自水平居中 |
| 文字宽高上限 | 墨迹宽 ≤ `0.52W`，高 ≤ `0.29H` | 最宽行 ≤ `0.84W`；两行总高（含间隙）≤ `0.62H`。相比源方图略收窄，左右各至少留 8% |
| 行间空白 | 无 | 第一行墨迹底边到第二行墨迹顶边 `0.07H`（28 px）；两行同字号，不拉宽短行 |
| 强调条 | 宽 `0.49W`，厚 `0.11H` | 宽 `0.66W`，厚 `0.075H`，仅第一行有条 |
| 对齐与遮挡 | 字与色条的联合外接框对准画布中心；底部 `30%H` 不放额外文字，为卡片标题留空 | 同样居中。在横版容器预览或编辑时，把**整个方图**放在正中，而不是把方图文字铺到横版两翼 |

**确定性绘制顺序**（设计工具和代码均可照做）：

1. **画背景。** 取像素中心归一化坐标 `u=(x+0.5)/W, v=(y+0.5)/H`。默认光心 `(0.50,0.12)`、椭圆半径 `(0.58,1.02)`。算 `d=min(1, sqrt(((u−0.50)/0.58)²+((v−0.12)/1.02)²))`，令 `t=d²(3−2d)`。各 sRGB 通道取 `round(light × (1−t) + base × t)`。只用一个色相族，不叠加图片、纹理或文字阴影。需要严格纯色时，设 `light=base` 即可。
2. **量字，不量行盒。** 加载主题指定的字体文件与字重，确认含所需中文字和拉丁字母。字距为 0、无描边；逐整数像素试字号，取同时满足表中宽、高上限的最大字号（最高从 `H` 起试）。按实际非透明墨迹框裁掉字体上下空白。若头条字高低于 `0.21H`，或次条任一行字高低于 `0.17H`，退回改短文案，不再缩字或挤字。
3. **定位强调条。** 两行按表中间隙叠放。以第一行墨迹底边 `b` 为基准、条厚为 `h`，条顶为 `b−round(0.72h)`，条底为条顶加 `h`；条用直角、实色、无阴影。条与每行分别沿 `W/2` 对齐。再平移整组，让**字和条的联合外接框中心**落在 `(W/2,H/2)`。条画在字的后面，不能遮掉白色笔画。长度不随短词强行缩到等宽。尺寸取最近整数像素，居中起点向下取整。
4. **导出。** 每篇按自己的 `lines` 排版；同一主题不重复随机选色、换字体或生图。输出不透明 sRGB PNG，不带参考线、长文章标题、圆角和界面暗罩。记录模板版本、断行、主题值、字体文件及校验值、渲染器版本；同环境同输入应得同版面。没有指定字体就报缺字/缺字体，不静默换字体。

### 两套可直接采用的主题

| 主题 | 默认字体文件 / 字重 | `light` → `base` | `ink` / `bar` |
| --- | --- | --- | --- |
| 青绿·宋（近似样本，不是官方字体） | 思源宋体简中 Heavy，`SourceHanSerifSC-Heavy.otf` | `#009C8D` → `#002B25` | `#FFFFFF` / `#E03A00` |
| 蓝灰·黑（上方示例） | 思源黑体 CN Bold，`SourceHanSansCN-Bold.otf` | `#45678F` → `#14243B` | `#FFFFFF` / `#AD481E` |

青绿主题把光心亮度略调低，以保留缩略图中的白字边缘。换色时先定品牌底色，再选同色系亮色，最后选与背景不同色相的条色；不要只改底色却让文字和条融在一起。换字体后重新量字，尤其检查 `FDE` 与中文的视觉重量。不要依赖某台机器的“宋体/黑体”系统别名。

**复现样例的输入与检查点。** 蓝灰·黑主题，头条 `lines=["项目复盘"]`，次条 `lines=["三步","复盘法"]`。用 Pillow 12.3.0、上述黑体文件（SHA-256 `62383707c086a32f3afd5e293f34c7eff64c7fea31f579fdc6cbe34d920519a6`）按整数像素取墨迹：头条字号 **119 px**、墨迹 **470 × 115**、色条 **461 × 44**；次条字号 **114 px**、两行含间隙 **336 × 246**、色条 **264 × 30**。其他渲染器的抗锯齿边界可能相差几像素，以占比和缩略图验收，不强求跨平台逐像素一致。

## 3. 裁剪、交付与验收

- **头条和次条是不同文章时**，各交自己的文件，例如 `01-lead.png`、`02-secondary.png`。若编辑工具只接受横版母版，次条以 `940 × 400` 为容器，将排好的 `400 × 400` 方图放入中央 `x=[270,670)`，两翼只延展背景；裁中心 1:1 后必须与独立方图一致。**不要求头条一行字也挤入这个方区**：样本头条字宽约半幅，已大于中心方区宽 `1/2.35≈42.55%`。
- **同一篇文章需要两种展示效果时**，并非给一个 `news` 对象填两个封面 ID。可借用李飞的拼版做法：横版 `940 × 400` 放左，方版 `400 × 400` 放右，合成无缝 `1340 × 400` 素材。对同一素材以 `a=940/1340≈0.701493` 分界：`2.35_1` 选 `(0,0,a,1)`，`1_1` 选 `(a,0,1,1)`（顺序 `x1,y1,x2,y2`，传参时用十进制字符串）。这是**两个有意选定的裁区**，不是让客户端自动居中裁整张拼图；无法指定裁区时不要上传拼版。
- **平台边界**：微信 [`draft/add`](https://developers.weixin.qq.com/doc/service/api/draftbox/draftmanage/api_draft_add.html) 的 `news` 支持 `2.35_1` 和 `1_1`，每篇文章有自己的封面素材和裁剪信息。接口不规定“必须用某字体、必须居中”，也未保证每个客户端都按文章序号选某个比例。上传永久素材、每篇一个 `thumb_media_id` 等发布细节见[已有接口调研](wechat-mp-draft-cover-per-article.md)。

**交付前检查：**

- [ ] 在约 **370 × 157** 的头条预览和 **56 × 56** 的次条预览中，不放大也能逐字读对；尤其检查宋体细笔画、数字和英文。若不能，先减字或换较粗字重，不把标题撑满画面。
- [ ] 头条一行、次条两行；文字与条作为整体居中（整数取整允许 1 px 误差），第一行底部能看到色条、字形不缺笔，第二行没有额外下划线。
- [ ] 用实际长度的文章标题模拟卡片底部两行文字：长标题不与大字打架，也没被绘入 PNG。方形裁剪后四周均有背景，左右不丢字，不露出拼版另一侧。
- [ ] 换品牌色后，在光心和色条两处检查字色对比；建议大字最弱处也至少 **3:1**（本规范的检查阈值，不是微信门槛）。最后到微信草稿预览验证两种展示位，不把本地缩图当作发布实测。
