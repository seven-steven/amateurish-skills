# 04: 图表无法忠实呈现时阻止发布，并保留网址引用

**What to build:** 当图表无法在首版支持范围内完整呈现时，用户获得定位到源图块的明确错误，而不是一张静默丢字、丢线或丢资源的图片。图内普通网址则保留为图注中的网页引用，继续沿用外链转脚注流程。

**Blocked by:** 02 — 发布第一张离线渲染的中文 Mermaid 流程图。

**Status:** ready-for-human

- [ ] Mermaid 语法错误、不支持的语法／图表、渲染限制超限及栅格化失败使构建非零退出；错误包含对应图块或源位置和可行动的原因，便于 agent 修正后重试。
- [ ] 对图内外部图片、自定义图标与公式排版明确拒绝并解释首版边界；这些输入不会触发外部资源下载，也不会在关闭扩展后静默丢弃原始信息。
- [ ] 对可检测的缺失字形、未落实的样式或变量、裁切和图形内容缺失增加显式校验；不能仅因栅格化 API 没抛异常就认定图表成功。
- [ ] 对超出渲染器或微信正文图片既有限制的输入、尺寸和 PNG 产物明确报错，避免在发布时才发现图像不可接受。
- [ ] 图内超链接的目标和关联说明保留到可阅读的图注引用；普通网页引用经现有流程生成编号脚注，相同 URL 共用编号，公众号文章链接沿用可点击行为。
- [ ] 对有效图与错误图混排的文章，整次构建失败；部分生成的图片与文章不会被当作完成产物进入上传或推草稿，也不会把上次成功产物宣称为本次构建结果。
- [ ] 自动验收分别覆盖语法错误、外部资源、图标、公式、缺失字形、图像／渲染限制及可检测的内容损失，并证明拒绝发生在资源下载、图片上传或草稿提交之前。
- [ ] 通过真实 CLI、解码后的 PNG、文章图注和模拟上传／草稿正文验证正常链接保留与错误阻断；测试从 `npm test` 可达。图片的最终手机可读性仍需用户预览确认，不宣称自动校验可替代完整视觉验收。

本票与多图／类型扩展票可以并行；错误策略和资源边界统一作用于所有图表类型。

## Comments

自动验收覆盖错误阻断、字形、资源限制、图块行号及不完整构建隔离。审查发现的链接说明丢失已补回归：图注保留节点名称和说明，同 URL 的不同节点说明保持各自关联，脚注仍去重。详见 [验收记录](../verification.md)。
