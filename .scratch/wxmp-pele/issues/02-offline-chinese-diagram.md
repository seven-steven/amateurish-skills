# 02: 发布第一张离线渲染的中文 Mermaid 流程图

**What to build:** 用户在发布副本中保留一段中文 Mermaid，沿用现有发布命令即可得到实际可见的 PNG，并通过图片上传进入文章预览与草稿正文。无需手工打开在线渲染站点、执行图片转换命令或安装中文字体。先用最小流程图贯通完整链路，不为图表类型设置额外白名单。

**Blocked by:** 01 — 上传与预览共用同一份构建产物。

**Status:** ready-for-human

- [ ] 真实 CLI 自动完成 Mermaid → Pele SVG → PNG → 文章图片引用 → CDN 上传 → 预览；模拟推草稿所用 HTML 与用户确认的上传后预览一致。
- [ ] PNG 能被实际解码，具有有效尺寸和非空图像内容；中文节点、箭头、标签、条件及示例数值完整可见。验收不止检查 PNG 文件头或 HTML 中出现图片标签。
- [ ] 普通源码、命令、配置、日志及代码中作为示例展示的 Mermaid 围栏保持原样；只处理真正的 Mermaid 图表块。
- [ ] 使用固定发行版本的 Pele 与 `@resvg/resvg-wasm`，随 skill 分发其运行所需 JS、WASM 和一份完整、未裁剪的简体中文字体。首版不引入字体子集生成工具链。
- [ ] 在既有 Node 运行环境中，仅复制安装后的 skill 目录即可离线构建。宿主无需额外安装 npm 包、Chromium、系统图像库或中文字体；构建阶段不请求在线渲染服务或字体服务。
- [ ] 分发体积允许必要增长：已核实的完整中文字体约 16.4 MB，WASM 约 2.5 MB，另有 JS；交付时记录实际体积、依赖版本与资产校验信息。
- [ ] 字体度量与栅格化使用相匹配的字体；Pele 输出的配色和 CSS 变量在栅格化前被落实为可正确渲染的样式，避免仅生成了图片但文字或连线不可见。
- [ ] 按既有运行时产物约定保留可编辑 Mermaid、中间 SVG、PNG 及适配后的文章；输入笔记正文不变，安装后的 skill 目录不承载用户运行时状态。
- [ ] 语法错误或渲染失败使构建非零退出，不将 Mermaid 源码块冒充已完成图表。缺失或损坏的分发资产有可定位的诊断，发布前检查能发现这些问题。
- [ ] 构建脚本可重建所提交的运行产物；补齐实际固定版本的许可文本和归属说明，覆盖 Pele 的 MIT/ISC 声明、resvg 的 MPL-2.0 及对应受许可源码获取信息、字体的 OFL 声明，并核查所分发组件的必要第三方声明。
- [ ] 首张图的 CLI、图像解码、模拟 CDN 与草稿正文回归测试从 `npm test` 可达；离线、无浏览器、无系统中文字体的安装验证覆盖 macOS 与无桌面的 Linux。验收不自动调用真实公众号。
- [ ] CLI 契约和分发说明与新增的本地成图能力一致，不再将图表运行所需资产描述为仅有一个 JS 文件。

实现依据是 Pele 的 Mermaid → SVG API，以及 resvg-wasm 的本地 WASM 初始化、字体缓冲区输入与 PNG 输出能力。具体集成兼容性必须由上述真实构建和图像验收证明，不能仅依据上游功能描述推定通过。
