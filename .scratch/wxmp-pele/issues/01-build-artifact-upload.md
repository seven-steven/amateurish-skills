# 01: 上传与预览共用同一份构建产物

**What to build:** 用户完成文章构建后，上传、预览与推草稿消费同一份构建产物及其中的图片引用。现有普通配图流程保持可用，同时允许后续构建步骤加入生成图片，而不会因为上传重新扫描原始笔记而漏传。这是图表集成之前的必要预重构。

**Blocked by:** None (can start immediately).

**Status:** ready-for-human

- [ ] 上传以构建后文章中的图片引用为准，保留对应的资源解析上下文；来自输入笔记的相对图片与构建目录中的生成图片都能定位到正确文件。
- [ ] 同一文章的构建、上传后预览与推草稿使用一致的正文；上传只重写发布产物，输入笔记正文保持不变。
- [ ] 构建产物可核验其所属输入笔记。对另一篇笔记执行上传、预览或推草稿时明确拒绝，且不会修改其他文章的产物或向服务端发送错误内容。
- [ ] 输入笔记在构建后发生内容变化时，提示重新构建，避免将新输入与旧产物混合。无法核验归属的旧产物同样提示重新构建。
- [ ] 默认输出与显式指定输出目录都能识别其构建产物；不因输出方式不同而退回另一篇文章的最近构建。
- [ ] 原有本地图片、远程图片、data URL、上传缓存与重复上传行为保持兼容；解析路径的基准不会因文章转移到构建目录而丢失。
- [ ] 经真实 CLI 与模拟上传服务验证：普通图片能完成构建、上传、预览及草稿正文组装；构建后加入的图片不会漏传；错误归属与过期输入在发送请求前失败。相关回归测试从 `npm test` 可达。

范围限于构建产物的归属和消费，不扩展历史任务管理、多会话调度或新的发布命令。
