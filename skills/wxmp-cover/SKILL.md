description: 为微信公众号文章提炼封面短标题，并在本地生成头条横图、次条方图、横方两张或可居中裁方的单图。用于从标题、正文或 Markdown 做封面，以及按品牌字体、配色重出封面；不发布草稿。
---

## 输入与选词

1. 接受一篇文章的标题、正文、粘贴文本或本地 Markdown 路径。是路径就先读文稿；按篇处理。若没有文章信息也没有指定短词，先索取其中一项。完整文章标题是卡片文案，不直接画到图上。
2. 从文章实际内容提取「对象 + 动作/结果」，给出一个首选和两个备选。每组准备一行头条词（约 3–6 个汉字量级）和按语义断开的两行短词（每行约 2–3 字）；保留 `FDE` 等专名，不截取长标题开头，不补写文章没有的结论。用户给定的封面词或换行是约束，优先保留。比如“听完 FDE 大会，我做了个 AI 工作台给老板试用，首单就收了 6000”：首选 `FDE交付`，两行 `FDE` / `交付`。
3. 直接用首选出图，不等选择。标题提炼由当前 agent 完成；绘图使用随包代码与字体 **SVG → PNG**，不调用生图 API。

## 渲染与交付

从本 skill 的实际安装目录定位 `scripts/render.mjs`（与本文件同级的 `scripts/`）；工作目录留在用户项目。下例的 `$SKILL_DIR` 替换为实际安装目录（不是预置环境变量），短词替换为本篇的选择：

```bash
node "$SKILL_DIR/scripts/render.mjs" --lead 'FDE交付' --line 'FDE' --line '交付'
```

- 把用户本次指定的 `--mode`、`--theme`、`--output-dir` 透传；没指定的选项**省略**，让命令读取配置，不自行补默认值。`头条/lead` 用 `--lead`，`次条/secondary` 与 `单图/single` 用两次 `--line`，`两张/both` 用两者。模式未知时可以同时传入两套文案，命令只渲染选中的版式。把每个标题和路径作为独立字面参数传递，不将用户文本拼成 shell 程序。
- 成功：从 stdout JSON 的 `files` 读取结果，列出采用的文案、实际断行、每张 **PNG 的绝对路径**，再给两个可替换的文案（不额外出四张图）。同目录保留 SVG；单图注明中心裁成 1:1 后文字仍完整。止于本地交付，不上传、不写草稿。
- 若**自动建议**的短词被提示字太长，精简或改断行再渲染；若是**用户指定**的文案不适配，说明原因并给可选修改，不擅自改字。缺字体/缺字形或配置报错时带出具体字段或文件，不用别的字体或图像服务掩盖错误。
- 用户要保存默认模式、输出目录、命名主题，或询问字体/字重与配色时，查 [README 的配置说明](README.md#配置) 和 [示例](config.example.json)。单次覆盖不写入用户配置。
